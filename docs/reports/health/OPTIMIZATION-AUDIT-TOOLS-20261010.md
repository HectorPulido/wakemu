# Tooling and observer optimization audit

Date: 2026-10-10. Scope: profiler-service, cron-service, client-tools, and sniffer. This is a source audit, not a measured attribution of the reported world freezes. No services were deployed or restarted for this audit.

## Ranked findings

| Priority | Finding and evidence | Expected benefit | Proposed validation |
| --- | --- | --- | --- |
| P1 | `sniffer/java/CaptureAgent.java:275` synchronizes every capture event, serializes JSON, writes a line, and flushes the writer on the calling thread. `observe()` additionally copies each ByteBuf, Base64-encodes it, and collects pipeline metadata. Network interception therefore performs filesystem work in client Netty callbacks. A flush drains the Java buffer; it does not imply an fsync, but can still block on the OS/filesystem. | Lower client network callback latency and distinguish client-side diagnostic overhead from server delay. | Compare callback p50/p95/p99 and client frame/network latency with capture enabled and disabled under identical traffic. Implement a bounded single-writer queue, batch flushing, explicit overflow counters, and a lightweight metadata-only mode. Preserve packet order and provide an explicit full-fidelity mode for protocol investigations. Do not silently drop events. |
| P1 | `server/profiler-service/service.py` artifact downloads use `destination.read_bytes()` and then one `wfile.write(payload)`. Retention permits approximately 1 GiB total artifacts and an active capture can temporarily exceed the cap, so concurrent downloads can allocate large files independently. | Bound observer memory and avoid swapping during investigations. | Stream fixed-size chunks from an opened file, preserving content length and rejecting symlinks; test a large artifact and disconnected client. Assert bounded RSS instead of only correct response bytes. |
| P2 | Profiler `/status` scans and parses every retained `capture-*.meta.json` while holding the same lock as capture start/finish/prune. At 60-second chunks and one-hour retention this normally means approximately 60 metadata files per status call, not an unbounded lifetime history. Frequent polling or concurrent callers multiply this filesystem work and delay sampler lifecycle access to the lock. | Lower status latency and reduce recording gaps caused by observer contention. | Cache metadata by filename/mtime or maintain a completed-chunk index; copy metadata references under the lock and perform filesystem reads outside it. Compare status latency and capture rotation gaps at 1/10 concurrent polling clients. |
| P2 | Profiler timeline `run()` serializes the complete `performance-latest.json` report every five seconds into minute JSONL files. Cost scales with report size and duplicates histogram/feature metadata even when unchanged. `prune()` stats each retained artifact on each timeline iteration. | Lower observer disk bandwidth and CPU; keep the retention budget useful for actual sampled stacks. | Measure report bytes, timeline bytes/hour and observer CPU; store a report version/hash plus compact changing counters or only append a full report when its version changes. Keep enough snapshots to interpret old captures independently. Cache directory metadata or prune less frequently if measurements justify it. |
| P2 | `server/cron-service/service.py:http_action` polls HTTP 202 work every 100 ms using fresh urllib requests. A ten-second pending task can generate roughly 100 polling requests. `Scheduler.tick()` invokes task actions serially, so a slow pending action can delay later tasks and the next scheduler tick. | Reduce scheduler request churn and improve timely execution of other jobs. | Use bounded backoff, e.g. 100 ms increasing to 500 ms, within the original deadline and with immediate lease-loss checks. Instrument poll count and action duration first. Any concurrency change must preserve occurrence IDs, retries, leases and exactly-once effect fencing. |
| P3 | `client-tools/local-client.sh` recompiles and repackages guard, desktop, planting and capture agents for every launch, including `--check`; `sniffer/build-capture-agent.sh` compiles seven Java sources each invocation. It packages the shared classes directory, which can retain obsolete classes. | Faster client startup and cleaner deterministic artifacts; no steady-state server benefit. | Build into isolated temporary directories and publish atomically. Cache by all source bytes, JDK/compiler flags and relevant client JAR versions; test concurrent two-profile launches and invalidation after changing a dependent source. Do not use timestamp-only caching that could deploy stale hooks. |

Retain only records required for output and provide incremental extraction where API contracts allow it. ## Existing efficient behavior worth preserving

- External py-spy sampling is nonblocking, configured at 25 Hz, and uses bounded retention. Including idle stacks is useful for blocked-thread investigation; it is not equivalent to CPU utilization.
- `client-tools/diagnostics/gui_capture_tail.py` maintains file offsets and incremental stream reassembly rather than rereading the whole capture on every poll. A large first backlog can still allocate a large chunk; bounded reads are a possible follow-up if observed.
- The cron configuration enables only explicitly selected tasks. Poll timeout, occurrence IDs and lease checks must not be weakened to improve nominal timing.
- No source finding alone proves the checkpoint freeze cause. Correlate server profiler, watchdog stacks, CPU/RSS, database waits, and client callback latency using the same timestamps.

## Language review and changes

Comments and docstrings in the owned services and tooling are already English. The developer CLI authentication messages in `sniffer/authenticate.py` were translated to English. Spanish desktop login UI strings remain localized user-facing text. Protocol action identifiers and Unicode codec fixtures were preserved: renaming identifiers or removing accented test strings would change compatibility or coverage rather than translate developer prose.

## Validation

No runtime optimization was deployed by this audit. The authentication message change leaves request, credential, and error-handling semantics intact. The shared regression-test agent verified profiler-service tests (17/17) and `test_capture_audit` (1/1). `python3 -m py_compile sniffer/authenticate.py` passed after the final message translations. No live authentication requests were issued.

## First cautious implementation: artifact downloads

The artifact endpoint now opens the validated file once and streams chunks of at most 64 KiB instead of allocating the complete artifact. It obtains content length from that open descriptor and sends only that initial size, even when an active timeline grows. Unlinking a retained file does not interrupt an already open download. Symlinks are rejected at open time as well as during route validation; non-regular files are rejected. A client disconnect closes the reader and connection without propagating a request-thread error.

Expected benefit: application payload-buffer memory changes from O(artifact size) to O(64 KiB) per download, excluding HTTP/kernel buffers. This is a bounded-memory improvement, not a measured reduction in world tick time. No world or profiler deployment was performed by this worker. Four focused regressions cover chunk limits and exact HTTP bytes/content length, midstream disconnect cleanup, growth after headers, and symlink substitution at open time.

Validation after implementation: `python3 -m unittest discover -s server/profiler-service/tests` passed all 21 tests (0.760 seconds).
