# Fresh retained-container scans and private criterion syntax reuse

The user reported approximately 4.5–5-second casts around 07:11 and 07:33 UTC. The 07:33 continuous capture has a gap, so no sampled hotspot is attributed to that request. The 07:11 audit shows distributed condition/property/retained-replay work and an already separately addressed topology JSON load. The following changes remove demonstrated repeated work without caching mutable combat authority or altering spells.

`NativeRetainedRuntime.synchronize` previously rescanned all owned stat/group/area effects once per container fact. It now computes current state-container users once per operation and prunes against that local set. There is no stored cache or cross-operation reuse; deletion and reparenting are visible on the next call. Unhashable malformed values retain legacy equality behavior through a fallback. A synthetic 1,000-child, 300-container, 30-operation membership benchmark measured 0.2537 s versus 0.0010 s (253.7x for that isolated scan).

`evaluate_condition` privately reuses parsed criterion ASTs only. The public parser still returns fresh mutable ASTs for tools. Evaluation and unsupported-branch validation execute against current context every time. The LRU admits at most 512 expressions of at most 2,048 characters and 256 AST nodes; invalid syntax and larger expressions are not retained. A representative 10,000-parse benchmark measured 0.4010 s uncached versus 0.0047 s cached (84.8x for parsing only).

Three syntax-cache tests pass on the host, covering fresh state/deck outcomes, public AST isolation and bounds/errors. Three retained-scan regressions cover all owned collections, deletion/reparenting, malformed equality parity and record/order pruning; these require the mounted PostgreSQL-backed catalogue environment and were delegated alongside the broader condition/container/replay suites. Neither benchmark is a full-cast or live-latency claim. No server restart was performed by this task.
