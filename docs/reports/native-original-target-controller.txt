GetEffectTargetOriginalController: contrato nativo

Lexer eQb119/eQd179 -> eKc. Firma estricta sin argumentos.
eKc.d devuelve0 si el tercer argumento (runner actual) es null. Si ese
argumento es eZR consulta Qe.bbc/bfs, no el source de evento eZR.rIV.
Sólo un PV que implementa eHg permite dTD; otro PV devuelve0.
En otros contextos eKc usa eII.b(true,...), cuyo actor resoluble entrega dTD.

La distinción importa en una activación: eZR.I calcula caster/target
rebound para los argumentos del criterio, pero pasa this como tercer
argumento. Por tanto GetEffectTargetOriginalController conserva el target
del listener retenido; GetTriggeringEffectTarget continúa siendo el source.
ProbeNativeOriginalController.java ejecuta el criterio original y acredita
cinco casos: runner null0, PV original91 frente a target rebound202,
intercambio de args sin cambiar original91, PV null0 y eHg202.

Para eGj, dTD = dpr()?.aHm: null0. big.dpr -> dnH -> eGj.c(fight,this).
eGj.c vuelve a self si no hay controlador resuelto. fcb.aV -> fdt.aV
sólo consulta un controlador si está presente el estado 'controlled'.
La creación ordinaria PC/NPC sin relaciones registra self como controlador;
una autoridad de invocación o relación nueva debe acreditarlo explícitamente.
Para faV (faY/faZ registradas), dTD es bgZ.Sn del propietario, null0;
no se reemplaza por el UID del área ni por el controlador actual del caster.

Evidencias de bytecode: .runtime/local/native-original-controller-{eKc,Qe,
eZR,fcb,fdt,faV}.txt y .runtime/java/eGj-bytecode.txt.
No se debe inferir controlador de cuenta, owner_id de personaje, signo del
ID ni source/caster del evento. Una autoridad ausente permanece desconocida.

Integración acreditada: adapter.condition recibe opcionalmente el target
original de la fila retenida; OrdinaryHealingEvents.conditions lo suministra.
No se agregó metadata persistente a EffectInvocation ni se propagó el target
del listener a los hijos nuevos. El contexto del evento conserva sus propios
GetTriggeringEffectTarget y caster/target rebind intactos.

Validación: 39 pruebas conditions/adapter/helper pasan y una quinta prueba
adicional del helper confirma NPC fresco self y rechazo de relación cambiada.
