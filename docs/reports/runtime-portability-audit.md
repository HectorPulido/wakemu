# Runtime portability audit

The local `.runtime/` directory is approximately 111 GB. This is an audit of reproducibility and source preservation, not a declaration that a fresh clone can currently start the full server. Private data has not been copied into public source directories. The running stack and its database volumes were not restarted, reset or migrated by this audit.

## Classification

| Category | Examples | Repository treatment |
| --- | --- | --- |
| Unique project-written source | Native spell exporters and interactive registry diagnostic adapter | Preserve under `sniffer/java/`, parameterize private paths |
| Generated build products | Java classes/JARs, Python caches, venv, packaged launchers | Regenerate from tracked source; keep ignored |
| Historical source snapshots | `e18-*`, worktrees, staged server copies | Preserve locally; do not copy old implementations over current source |
| Private state | Tokens, credentials, player databases, certificates, logs, profiles | Keep ignored; initialize new secrets automatically |
| Original game material | Patched script backups, native catalog dumps, client-derived binaries | Keep private; requires extraction from a user-supplied client |
| Captured protocol evidence | `captures/`, official creation/dungeon captures, action payloads | Keep private; no automatic publication of user sessions |
| Research and benchmarks | Combat review folders, frozen validation, bytecode and generated graphs | Preserve locally; recreate through tools or replace tests with synthetic fixtures where possible |

The two largest directories are combat review folders (approximately 75 GB and 25 GB). Local runtime state occupies approximately 7.6 GB. Their size is not evidence of a missing source dependency, and none were deleted.

## Sources rescued

`runtime-source-rescue.json` records original and preserved hashes for:

- `sniffer/java/InteractiveRegistryDiagnosticAgent.java`: read-only interactive object registry diagnostics.
- `sniffer/java/VerifyPatchedClasses.java`: reflection-based movement/shortcut compatibility check.
- `sniffer/java/ExportSpells.java`: scalar spell fields and criteria, now accepts explicit client and output paths.
- `sniffer/java/ExportSpellCosts.java`: native spell costs across levels, now exports all definitions instead of a fixed player spell roster and accepts explicit paths.

Existing monster, exchange metadata, food and territory exporters already have source under `sniffer/java/`; duplicating older runtime copies would not improve reproducibility. The rescued exporters are developer tools, not a complete native catalog rebuild pipeline.

## Removed generated-file assumptions

Three dungeon/bootstrap source tests now inspect `server/local_game_server.py` rather than a private historical overlay. The mouse diagnostic now builds `UiSnapshotAgent` and `AttachAgent` from the existing repository sources and discovers the installed JDK; it no longer requires a pre-existing private JAR or a hardcoded JDK path.

To generate fresh runtime directories and credentials:

```sh
python3 tools/prepare-local-runtime.py
```

This creates private password/token files with mode 0600 and never replaces existing credentials. It does not initialize game catalogs or player state. Certificates continue to be generated by the server entrypoint. Java agents are generated by the client tool build scripts.

## Fresh-clone blockers still present

1. **Protocol templates and ordered bootstrap replay.** `server/local_game_server.py` reads a specific historical `frames.jsonl` at startup, indexes frame 44, selects captured character/appearance data, and replays slices by position. Compose mounts that exact private file. Moving a raw capture into Git would expose session data and would retain the single-session dependency. The durable replacement is generated protocol templates and explicit bootstrap message builders, with synthetic regression fixtures.
2. **Native catalogs.** The active PostgreSQL catalog contains 7,482 documents. Source JSON files were deliberately removed after database migration. A database volume or private dump currently supplies these catalogs; an empty PostgreSQL instance cannot reconstruct them from the repository alone. A complete extraction/conversion orchestration from the supplied client is required. Publishing the full player database dump is not a substitute.
3. **Build orchestration.** The AI Dockerfile requires an authoritative world image (`WORLD_IMAGE`); its default is not automatically built under that name by the current Compose configuration. A fresh build needs explicit world-first build orchestration and matching image/revision arguments.
4. **Research fixture dependencies.** Some integration/oracle tests and report generators still read captured probes, native dungeon configurations, mechanics graphs and benchmark cases under `.runtime/`. They require separately generated inputs or sanitized synthetic fixtures; not all are ordinary unit tests.

Paths under `.runtime/` used only for output (logs, packages, compilation, captures generated by the sniffer) are correct and do not need relocation. Inputs necessary for behavior must instead be generated from the supplied client or replaced by project-owned builders. No fallback to filesystem JSON catalogs was added.

## Validation

- Runtime preparation: three regression tests cover private permissions, repeat execution preserving credentials, empty secret rejection and symbolic-link rejection.
- Rescued Java sources: compile against the supplied compatible client.
- UI diagnostic agent: built from repository sources without using the old runtime classes/JAR.
- Three migrated dungeon/bootstrap modules: 11 tests pass against repository source with installed server dependencies.
- Runtime preparation and client launcher/patch tests: 25 tests pass.
- Full fresh-clone startup remains unverified and blocked by the dependencies above; the existing running installation is not proof of portability.

## Follow-up: repository snapshot and build order

At the user's explicit request, the complete development dump and checksum were moved to `database/backups/`, with Git LFS tracking for the archive. Compose now initializes an empty PostgreSQL volume from that dump, using `wakemu_runtime` for world and AI. This supplies native catalogs for a fresh installation without requiring the former private catalog source files. Existing database volumes are never overwritten on normal startup.

Compose uses a shared configurable world image name for the world build and the AI base-image argument. `tools/build-local.sh` builds world before AI and cron without restarting services. Configuration and initialization command orchestration were validated; no fresh database volume restore was performed.

The specific captured `frames.jsonl` bootstrap template remains a full server startup blocker. Research fixtures remain a separate limitation for reproducing the complete historical test/report suite. The native catalogs remain client-derived material even though the user elected to keep the development dump alongside source.

## Follow-up: portable test fixtures

Six deterministic regression inputs moved to `server/test-fixtures/combat/` and `server/test-fixtures/dungeons/`, with source provenance and SHA256 hashes in `server/test-fixtures/manifest.json`. The oracle tests now require these checked-in fixtures instead of silently skipping when private research files are absent. The HUD threshold test no longer writes an unnecessary private JSON report. The portable launcher test builds its own package in a temporary directory rather than inspecting `.runtime/distribution/`. Full captured sessions remain private.
