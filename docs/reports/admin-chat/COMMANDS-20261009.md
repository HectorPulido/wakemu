# Development chat commands

These commands follow the existing database-backed command permissions. Changing another connected character requires administrator privileges. Targets are exact character names, case insensitive, supplied as the final optional argument. Quote names containing spaces. Omit the target to act on yourself.

| Command | Example | Expected result |
| --- | --- | --- |
| Add kamas | `!kamas 10000 "Prueba Oficios"` | Adds 10,000 to the target account wallet, updates the client and persists across reconnect. |
| Grant item | `!item 25069 1 Audiluna` | Grants one La Cola to Audiluna's inventory. |
| Raise level | `!nivel 60 Audiluna` | Persists level 60; reselect the character to refresh spells and points. Lowering levels is rejected. |
| Spawn mobs | `!mob 1 10 2 Audiluna` | Spawns two native reference 1 mobs at level 10 near Audiluna, respecting map/instance restrictions. |
| Teleport | `!tp 527 -128 -33 0 Audiluna` | Moves Audiluna to the validated native destination. |
| Search items and mobs | `!buscar JALATÓ` | Shows native IDs, names and item/mob labels, ignoring accents/case and tolerating spelling mistakes. |
| Search only items | `!buscar item jalato --pagina 2` | Shows the second page, eight results per page. |
| Search only mobs | `!buscar mob jalto` | Returns fuzzy matching native mob references and levels. |
| Save pending positions | `!checkpoint` | Starts the scheduled position persistence callback asynchronously and reports completion, saved positions and duration. |
| Check save result | `!checkpoint 1` | Shows the status of save receipt 1. |
| Check targeted command | `!resultado RECEIPT` | Shows completion or the rejection reason for a targeted queued command. |

English aliases remain supported: `!level`, `!teleport`, `!monster`, `!search`, `!ids`. Names may also use `@Audiluna`.

Targeted changes run on the destination session's owner thread. Combat, haven bag, inventory capacity, native geometry, active session generation and permissions are checked at execution. A disconnected or replaced target session cannot inherit queued work.

## Acceptance sequence

1. Connect two test characters. Record both wallet balances and inventory contents.
2. Run `!buscar Jálato`, `!buscar JALATO`, and `!buscar jalto`. All should find Jalató mobs and relevant items; use the item/mob filters and page option.
3. Grant `!item 25069 1 TARGET` and `!kamas 10000 TARGET`. Only the named target should receive the updates. If a receipt is returned, query `!resultado RECEIPT`. Reconnect the target and verify persistence.
4. Use `!nivel`, `!mob`, and `!tp` with a connected target, then omit the target to verify the original self-command behavior. Commands that alter combat state must reject a target currently fighting.
5. During a shared combat, run `!checkpoint`. Continue moving/playing on the other character. The command must return promptly and subsequently report success or a bounded failure without freezing unrelated combat.
6. Try an unknown target, malformed quantity, unauthorized account and a target that disconnects before execution. These must reject without modifying another session.

The active scheduler currently calls `positions_flush` every two seconds. `!checkpoint` invokes that same callback over all pending positions; it does not claim to checkpoint inventory or arbitrary Redis keys, which have separate persistence paths.
