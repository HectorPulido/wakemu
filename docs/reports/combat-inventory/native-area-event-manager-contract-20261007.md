# Native area state-manager lifecycle boundary

`Qe.L` dispatches local phases through generic `PV.a(BitSet,Object,byte)` to caster (reversed channel) followed by target. The same PV can receive both. It does not require `eGj` or fighter characteristics. `faV` extends `Qq` and implements PV/eHg. `Qq.a(BitSet,Qe,byte)` first forwards to its actual `bax()` Qf, before the separate area-trigger predicate. With property `fbo.rNB` (12), `faV.bax()` constructs an `eZV(this)` manager. Thus a registered faY/faZ area with a proved actual Qf can receive generic state L1–L4 events.

The shared lifecycle previously rejected area state targets because its healing-derived implementation required both identities in `preview.actors` and inspected fighter undead property even for explicit generic events. The repair uses actual `state_manager` registration for explicit event IDs, preserves ordinary actor authority for fighters, and computes the eXs undead rule only for the healing path. Areas acquire neither HP, resources nor turns.

Global propagation is a different contract: `eZR.L` calls `PN.bab().m(caster)` after local delivery. `fcb.m` selects the caster-only PV iterator for `fbZ.rRo`; otherwise its `fcd` iterator combines fighters, registered Qs areas and fbX extra PV registrations. Multiple matching global managers including areas require an audited combined iterator order; the repaired path keeps that case explicitly unsupported. A single relevant actual area manager needs no ordering inference.

Clone guards still need separate native authority. `eZR.i` checks the retained original target's `PV.baG`; `Qe.bbJ` checks `PV.baK` before and after L2. Area Qq returns its `bhi` field for both; constructors initialize false, and `Qq.b(PV)` sets true. **Unregistering an area with Qs.b is not proof that Qq.b ran.** A retired manager's existence cannot establish either boolean. Clone target positions can come from an actual state manager without inventing fighter data, but area removal guards must retain their true provenance.

`combat_runtime_adapter.condition` already resolves area state-ledger aliases without fighter resources. The subsequent integration validates clone PV identities independently of fighters, reads the original area target's explicit `baG`, and uses registered PV positions. State application checks area `baK` before and after L2. The general rebound group lifecycle and combined global iterator still need complete verification; these changes do not certify every clone path.

The local phase now resolves a registered PV even when Qf is authoritatively null. It omits Qf listener replay in that case and preserves an explicit blocker for matching own entry masks. The state handler rejects a null-Qf target after L1 and before L2/application. The tests cover actual manager recipient order, null-Qf disjoint entry masks, unknown/overlapping cases, prepared-runner cleanup and continued fighter requirements for healing. Root delegates execution and broader regression verification to Luna. No world, Docker, DB or AI operations were performed.
