# Native family426 triggered-spell boundary

Status: partial source reconstruction; server execution remains absent. This
family must not receive implemented coverage because its request can be built.
It affects nineteen states in the selected-root state inventory.

The installed native `eYZ` extends `eZR`, not the ordered-group `eYg` runner.
Its `C(Qe)` resets private `rHe` to true; with three or more parameter pairs,
it evaluates parameter2 at the runner's `fRR()` level and compares with1. Its
`c(Qe,boolean)` evaluates parameter0 at fixed level1 to obtain the spell ID.
It then requires an `eGj` caster. A different caster calls `mu(true)` and
returns. A bound target contributes its actual `bcz/bcA/bcB` coordinates;
otherwise the destination is a fresh copy of `bbd()`. The invocation is
`eGj.a(spellId, copiedCoordinate, rHe)`. Extra parameter pairs are ignored.
`aWr()` resets `rHe` to true; `fQI()` constructs a fresh runner.

Fresh target selection also needs this runner's dynamic virtual owner flags.
`bbA()` defaults true and `bbB()` false. When parameter1 exists, they compare
its raw `So(1)` float with1, rather than evaluating its level-dependent value:
raw1 selects a cell; every other value selects actors. The shared owner
producer now implements these flags by the catalog's actual `eYZ` ownership.
This resolves selection authority, without registering family426 execution.

The actual installed `eGj.a(int,aBn,boolean)` bytecode is a single `return`.
The inspected `big`, `bjo` and `bje` classes do not override that signature.
This client hook proves the arguments crossing the boundary, not server
execution costs, spell level selection, critical selection, turn rules,
spell-book requirements, recursion, parent running UID, retained container
ownership, or eventual removal. Main player packet validation cannot supply
those facts for reactive casts without a separate server contract. No clone,
group-child application, successful spell cast or effect packet is fabricated.

`combat_triggered_spell.py` exposes an immutable copied request and explicitly
rejects a missing server executor. It has no handler-factory registration.
Five unit tests cover fixed versus runner levels, raw owner flags, copied
coordinates, private-field reset semantics, nonfighter suppression, missing
executor and malformed authority. Syntax compilation passed; the parent
validation agent owns execution of the unit tests. No services were touched.

Next required evidence is the server-side implementation or a protocol/script
trace specifying the hook's triggered-cast execution semantics. Until then,
family426 remains an execution gap in the state inventory and must not be
advertised as a working class mechanic.
