# General pre-target UI availability policy proposal

Client policy is now implemented in NativeSpellAvailability.java and the CaptureAgent bPO usable hook. It is not active in an already running client; relaunch is required. Server ownership/count inspection remains independent.

The installed bPO `usable` property resolves the real current actor's exact shortcut UID/book object and calls the native cast query with no target cell. That query evaluates the complete cast criterion. It can therefore return twV for an unmet target predicate before any target is selected. A valid-target query must continue to use the unchanged complete criterion.

Published casting metadata contains20 definitions with IsOwnSummon, spanning base breeds5/12/13/15/16 and additional granted actions;11 use # annotations. Osamodas breed2 has no such predicate in its cast criteria, but17 nonempty criteria include other target-dependent predicates, including HasStateFromUser7134, enemy/character/obstacle checks, and caster/target team comparison. A Cra/ref6349 switch or IsOwnSummon-only bypass would be incomplete and unsafe. Exact expressions are preserved in [the topology JSON](native-own-summon-pretarget-topology-20261008.json).

Proposed named Wakemu UI policy: preserve the original null-cell result for all statuses except twV. For twV, evaluate the existing full native cast query against actual candidate cells in the current complete native fight/map. Mark usable only when one query returns twD. Reuse the exact current actor, native book object and actual map surface/cell selection. Stop at the first valid candidate. Keep other cost, turn, usage, property, range and target guards intact. This is existential target availability, not replacement of a predicate by true. The selected-target cast still executes the original complete query and the server still validates the complete native criterion.

This policy requires a complete candidate domain including empty cells and actual selected native z surfaces; checking only fighter coordinates would incorrectly disable free-cell spells. It should cache only with explicit invalidation for actor/resource/book/terrain/QI/state changes, or initially avoid caching. No guessed z or whole-map scalar-height projection is allowed. If the domain is unavailable, preserve the original result. A live witness is needed to verify whether the observed gray spell actually fails this twV path or an earlier guard/book identity path.

The # wrapper sets the native alS presentation flag through cK(false). eTI's description generator observes bDA; amb.b and alr do not bypass evaluation based on that flag. Treating # as an unknown-target truth override is not supported by the bytecode.

## Implemented scope and verification

The hook only processes bPO.eH("usable") after the existing null-cell query returns twV. It first probes exact current PV coordinates, then the QI.X native selected surfaces within the native no-target maximum range plus caster radius. Each candidate uses the unchanged full query. Unknown authority, a missing exact raw-UID book, nonowned current actor, malformed map bounds or maps larger than20,000 cells preserve the original result. Other null-preflight statuses remain unchanged. There is no server mutation, artificial grant, criterion edit or cached availability. Alternative stacked surfaces not selected by QI.X are covered only when occupied by an actual PV. This can retain false negatives; it cannot enable a candidate rejected by the full native query.

The capture-agent build succeeds with the configured JDK 21 toolchain. The isolated policy fixture `sniffer/tests/ProbeNativeSpellAvailability.java` passes 21 assertions, including unrelated status/property, exact shortcut UID, missing summon count, insufficient AP, nonowned actor, native PV and empty-cell surfaces, unavailable QI, malformed map bounds, and a complete 100×100 candidate scan with deduplication. These are policy unit tests, not a live-client acceptance claim. Source relaunch/build uses the normal `client-tools/local-client.sh`, which rebuilds the agent. No relaunch was performed by this task.

## ASM verification regression and correction

The first hook loaded local slots 0/1 after the original query. The original obfuscated method has a stack-map frame where those locals are TOP; loading them caused a JVM VerifyError and interrupted character loading. The corrected hook replaces only the native INVOKEVIRTUAL query with a typed static adapter consuming exactly the same receiver and arguments and returning fyJ. It does not introduce local loads or change the original stack maps. The adapter calls the original query once before applying the UI policy. Verification passed against the real `bPO` class from `wakfu-client.jar` under JDK 22 with `-Xverify:all`, loading `eH(String)` through the capture-agent transformer. The verifier did not initialize the game client or connect to a server. Compilation and isolated fixtures alone would not establish bytecode validity.

The corrected combined agent passed real JVM verification: `-Xverify:all` with the javaagent loaded bPO from the actual wakfu-client.jar and resolved `public Object bPO.eH(String)` without VerifyError. The isolated policy probe also passed all 21 assertions after this correction. The verifier was a separate offline JVM; no running game client or server was restarted. Live login and spell availability still require the user's normal client relaunch.
