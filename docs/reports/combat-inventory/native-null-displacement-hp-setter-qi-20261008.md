# Null displacement and HP setter QI lifecycle

Three committed-class bulk failures reached family300 with a proved null recipient (effects326170/350171). Original `eXJ.fOt` and `eXK.fOt` return their target `bfs` only when it is a `fax`. Shared `eXD.c` resolves this first and cancels on null before geometry and caster-dependent checks. Null or a registered Qq recipient therefore produces a native no-op. An unknown nonnull PV identity remains rejected. The same native `fOS` carried-recipient guard cancels before path calculation.

Two further failures were classified as family16 (`eYO`, HP `set_current`), not orientation303. Original `eYO.c` calls `PA.on` and contains no `fcb` death or QI-removal operation. An actual HP operand can therefore become zero while the native fighter status remains IN_PLAY and its QI slot remains registered. Projecting HP0 into death or removal at this boundary changes the source contract.

The QI validator now accepts this IN_PLAY zero only when the complete owned PA raw-current producer validates the live raw value, current HP characteristic, minima/maxima clamp and actor HP together. Unknown HP0 still requires its prior death/lifecycle evidence and rejects. OFF_PLAY/OUT_OF_PLAY and retirement contracts retain their separate existing rules. No actor is forced alive, no history is deleted and no slot is reconstructed.
