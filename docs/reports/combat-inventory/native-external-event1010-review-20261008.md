## Implemented owned KO boundary

`combat_death_events.deliver_owned_death` now delivers the named
`wakemu.owned-ko-and-death-v2` policy after actual registered OFF_PLAY and
before event 1013 / terminal reconciliation. It preserves the actual lethal
running effect UID, caster, target, value, container and suppression facts.
Recipients are the caster's reversed channel 60, defeated target's local
channel 6, then channel 61 in the actual native global PV collection iterator.
Areas without Qf are skipped. Missing global topology is accepted only when
an authoritative subscription view proves no matching global observer.
A death sequence is recorded before synchronous replay to prevent recursion
or checkpoint reload from emitting the same boundary twice.

This is a consumer-backed Wakemu policy, **not a recovered original event
producer**. eZR.bcd recognizes event 1010 as a KO context. The installed
351404 listener binds target-code 5 to the actual lethal source target;
a null-source event would incorrectly retain its original self target.
The native Luminous Arrow tooltip describes temporary LOS transparency and
does not explicitly describe its KO reward. The native 351403 → 351404 →
351405 / 395194 chain supplies the separate reward-consumer evidence.
Events 1012 / 1015 / 1018 are not aliases of this KO boundary.
