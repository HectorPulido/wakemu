## Explicit missing dynamic producer

Profile identity comes from the owned collection, not from parameter0 of a307 effect.

Native family320/`eYG` handles capture and family859/`eWz` returns a summon to its owner's component. Family325/`eYH` toggles the native target's AI-enabled/control observer; families950 and952 are forced AP/WP values, not control. This review reads those contracts only and makes no change to the AI service.

Dynamic copies are additional producer families. Family 347 (`eZt`) evaluates the image's base breed and requested level, inheriting actual caster level when the requested value is nonpositive. Its `eHL` descriptor receives the actual caster breed, name, HP, source actor and copied visual configuration. Families 839 (`eZp`) and 994 (`eZq`) delegate `eZn.C`, whose `faB`/`faA` copy configuration constructs an `eHI` descriptor from the actual selected source actor. Their descriptor and copied actor contracts require separate coverage; the static family-307 book export proves neither. Evidence is saved in `summon-copy-native.txt` and `summon-copy-base-native.txt`.

`GetSpaceInSymbiot` is native `eLm`: it resolves CASTER regardless of ignored constructor arguments, returns -1 for proven null, non-`eHP` or null-component cases, otherwise counts null entries across the component's exact 10 slots. Native `biB.aQc` calls `dqt`, which initializes `bjd` and `bPo(owner UID)` for OSAMODAS (native breed 2) only when that component is absent. This proves an empty collection for that actual initialization path; it does not establish the contents of an existing character's collection.

The owned serialized producer is `biH.zm`: it reads `pd.SG.SK` (`yS`) through `eHX.b`. Each `yT.amT` (`tr`) entry supplies a signed-short profile reference `aaN`, name `VY`, and byte slot `Sj`; `yS.amS` supplies the selected slot. The importer clears the component, resolves each profile through the native descriptor factory, skips unresolved profiles, places the descriptor at the supplied slot and marks it available. `eHR.dA` accepts a profile reference without filtering, but this does not establish capture eligibility for every NPC. Family 320 separately checks the actual target and native capture guards.

The existing server has no complete owned symbiote component/storage producer. Captured profile identities and their ability closure must come from that actual collection, rather than from the 39 static profiles or an arbitrary monster catalog. Captured abilities remain class dependencies to inventory and implement, while general monster casting and AI remain outside this work.
