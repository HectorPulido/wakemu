# Dynamic group PA-null authority

Native `faV.b(PC)` literally returns null. `faY`, `faZ`, `faN`, `faX`, and `faU` inherit this implementation. Runtime resolution first validates the registered area PV/prototype through `registered_area_pv`; it does not infer absence from a missing dictionary. `faW.b(PC)` returns null only when its optional `jKz:eRF` is null. The existing verified closed faW constructor excludes all branches creating that container; only that attested constructor is accepted. Wall/trap overrides and unavailable faW constructors remain explicit unknowns.

`eYn.d` (913) distinguishes null PV from null PA. Null PV preserves inherited context. A non-null PV with null PA supplies value zero directly, bypassing the mode switch (including percentage division), then applies the native divisor/base/growth/rounding formula. `eYs.d` (1047) invokes `eYn.d` first; when both HP and virtual-HP PA references are null it preserves that inherited result. It does not replace it with a newly invented zero HP ledger. Existing actor snapshots remain mandatory and incomplete snapshots reject.

The production factory group-level callback and retained child-context callback now use the same full-fight PA resolver. Detached actor scope, active/retired verified area identity, signed level behavior, and flag16 transmission remain intact. Source bytecode evidence: `/tmp/wakemu-area-PA-current.txt`, `/tmp/wakemu-dynamic-group-pv.txt` (offline javap; not committed artifacts).
