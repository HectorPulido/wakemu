# Native runner HP0 eligibility

Native eZR.i tests the original PV.baG with the virtual bcd policy before
criterion/probability execution. Numerical HP0 is not this predicate.
The installed runner policy catalog proves eXt.bcd constanttrue for all seven
supported damage families. Base eZR.bcd admits flag15, its actual special
container25/reference2040 branch or event1010; missing dynamic authority is
not treated as false or fabricated as true.

Damage, healing and shared stat consumers previously rejected HP0 before
reading executable context. The common `verify_runner_target_life` now checks
the actual owned baG/baK status for HP0 targets after context verification.
An explicitly registered HP0/IN_PLAY target is eligible independently of HP.
An actual corpse requires a proven virtual bypass. Unknown HP0/legacy status
and unknown dynamic corpse policy continue to reject. State applicators have
separate existing PV gates and are not indiscriminately changed.

The trusted dispatched damage API accepts an optional native runner effect
for this exact path. Its ordinary default still requires a living target.
A second admitted burst runner on HP0 can deliver native arithmetic, packet
and lifecycle phases with0 actual HP loss. It does not register duplicate
death events or change an explicitly IN_PLAY target to OFF_PLAY solely
because its HP was already zero.

Three new regression cases cover kill-followed-by-damage delivery, explicit
HP0/IN_PLAY status, and flag15 versus unknown dynamic stat policy. Existing
unregistered HP0 damage rejection remains covered with a more precise error.
Focused validation is delegated to the test agent. This does not close all
retained DOT/state sequences, special container/event1010 dynamic bcd branches
or resurrection lifecycle semantics. No service was restarted.
