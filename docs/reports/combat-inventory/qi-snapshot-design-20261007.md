# Shared native QI snapshot contract

`combat_qi_snapshot.py` provides a pure snapshot of the serialized arena rectangle and signed-short masks, plus an optional explicitly complete population of registered QK obstacles. It is not installed in fight creation, persistence or runtime callbacks yet. No bootstrap, state, authority or caller files were modified.

The snapshot exposes native names `aK`, `P`, `Q`, `R`, `U` to keep distinct contracts visible. Bounds follow VE.aK, including Java signed-int upper-bound arithmetic. Mask indexing is QI.W: `(y-origin_y)*width+x-origin_x`. P requires in-bounds, an exact mask unequal to -257, and bit 128. Q tests absence of bit 128. R tests `(mask & -257) != -257`; it is not movement walkability. An existing rectangle cell carrying blocked bit 256 remains in bounds and R can still be true. No border or cell existence is derived from selected walkable cells.

Optional `RegisteredObstacle` records contain actual slot bcN ID (0..126), anchor XY and signed-byte radius (native nonpositive radius occupies only the anchor). Complete population authority belongs to the producer, not this helper. Duplicate IDs reject. U collects overlapping IDs across the native square footprint, clipped to bounds. The IDs are not affiliations. An unknown population raises in bounds; a complete population with no stored cell entry returns None, preserving QL.oY's native null distinction. Out-of-bounds U returns an empty set even without population authority. This helper represents a fresh registration population; retained empty QL entries after removal and other QL history are not reconstructed from obstacle records. Consumers must not silently equate absent native entries with a complete reconstructed lifecycle snapshot.

Integration should preserve the exact arena dictionary sent through `combat_wire.topology` at fight creation and checkpoint it. A lightweight callback can read snapshot.P for IsOnBorderCell. The current arena builder explicitly sets masks and must be the source; fight.cells or asset walkability cannot replace these masks. Registration lifecycle must independently capture bcN allocation, physical radius, active spatial membership, moves/toggles/removal and any persisted QL cell history before U is used as a fully equivalent live producer. A creator-supplied native registration population can support explicit freshness claims; the mere actor roster cannot.

QI.j(x,y,z) is deliberately absent. Native j calls QI.i and checks a returned Vy's bLD against -1; this depends on actual installed map-cell lookup and height. Serialized rectangle masks do not prove that asset result. No fallback boolean is provided.

Five focused unit tests pass for exact sentinel/bit behavior, blocked-but-in-bounds cells, unknown versus absent occupancy, square radius corners and overlapping IDs, and malformed masks/duplicate registration IDs. Command: `PYTHONPATH=server /tmp/wakemu-combat-review-venv/bin/python -m unittest server.tests.test_combat_qi_snapshot`. Evidence: `.runtime/combat-review-20261007/QI.javap`, `/tmp/wakemu-VE-qi.txt`, `/tmp/wakemu-QL-occupancy.txt`. No client or live-service verification is claimed.

### Proven integer domain

Footprint construction now rejects endpoints outside signed int32, and inclusive positive-radius loops whose upper endpoint is INT_MAX (native increment can wrap and fail to terminate). Python arithmetic is therefore used only in the proven terminating native domain. A radius-zero or negative-radius point outside QI bounds rejects as an invalid complete spatial registration entry: QI.b's nonpositive-radius branch returns before indexing, and QI.f only invokes spatial insertion for an in-bounds anchor. Such an object may have an allocated obstacle slot, but it is not an indexed occupancy record. These errors occur before the snapshot publishes its occupancy map.

A sixth regression covers INT_MAX/radius1, INT_MIN/radius1, and out-of-bounds zero/negative-radius registrations. All six tests pass. This helper rejects unsupported domains rather than claiming equivalence for native overflow or nonterminating loops.

### Minimal installation point (read-only review)

The function `create_placement` is in `combat_bootstrap.py`, not a separate placement module. It is the available boundary holding both the exact arena and newly constructed Fight, immediately after its Fight construction around line 224. Fight itself currently accepts walkable cells, placement cells and directed edges; these arguments do not contain the serialized rectangle masks. No independent caller-free change in Fight can recover the missing data correctly.

The bootstrap owner can attach a plain `fight.native_qi_arena` dictionary containing copied `x`, `y`, `width`, `height`, `cell_masks` immediately after construction. Runtime P callbacks can construct `NativeQISnapshot` from that data without obstacle population. Missing data stays unknown. The existing checkpoint snapshot walks Fight.__dict__, so this plain dictionary persists automatically. Storing the helper instance would fail `_plain`; storing the full arena is unnecessary and its bytes cell_flags also fail that serializer. Avoid reconstructing masks from Fight.cells.

`audit_active_spells.py` already constructs fights through create_placement and can receive this same exact arena attachment. Passive and isolated unit fixtures must supply their own explicit serialized masks; automatically building them from walkability would not verify the native contract. IsOnBorderCell registration belongs in the conditions/adapter owner's existing authority callback path, with actual target coordinates; this review did not modify those files or bootstrap.

### Exhaustive actual-client mask oracle

`sniffer/java/ProbeNativeQIMasks.java` constructs an actual QI subclass and sets its inherited rectangle and short-mask fields directly, without loading gameplay catalogs. It evaluates native P/Q/R/aK for all 65,536 short bit patterns in a one-cell rectangle. A compact byte per pattern contains P bit 0, Q bit 1, R bit 2 and aK bit 3. The Python helper produces an identical table: zero mismatches; both SHA-256 values are `e636f8b63bf4d13aa951e0d12c8b9830119152f53535d32dfef99f0db362f0d3`.

For every mask, four adjacent out-of-bounds coordinates also return false for all four methods. Native and Python probes additionally agree at INT_MIN and the wrapped INT_MAX+width upper-bound case. The private output directory `.runtime/combat-review-20261007/qi-mask-oracle/` contains `native-mask-flags.bin`, `native-proof.txt`, and `comparison.json` with SHA-256 provenance for the Java source, Python helper and all client library jars. Production Python and catalogs were not edited during this oracle run.

Compile/run: `javac -cp 'client/lib/*' -d .runtime/combat-review-20261007/qi-mask-oracle/classes sniffer/java/ProbeNativeQIMasks.java`, then `java -cp '.runtime/combat-review-20261007/qi-mask-oracle/classes:client/lib/*' ProbeNativeQIMasks .runtime/combat-review-20261007/qi-mask-oracle/native-mask-flags.bin`. This exhaustive oracle validates mask methods, not occupancy or asset-cell j.
