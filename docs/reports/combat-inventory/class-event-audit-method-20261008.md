# Reusable class event audit method

Apply the same source audit to every class. The Cra audit is the first concrete inventory; it is not a substitute for the remaining classes or a functional acceptance percentage.

1. Seed the class closure with every active/passive spell and source-backed innate state. Include state roots, child groups, granted spells, summon initial states and registered area roots. Record unresolved dynamic references and supplement older graph omissions from the actual catalogs.
2. Extract each listener's native masks, criterion, direct parent, owner, global/reverse subscription, target/caster recipe and flags. Mask indices0–5 select subscriptions; index6 declares emitted event bits. Preserve removal-only listeners and explicitly false display rows.
3. For every required event ID, locate a real production caller. Trace factory preparation, executor phases and retained activation/removal, rather than stopping at an event descriptor, dispatcher capability or catalog mask. Identify whether the exact source executes directly, as a clone, or against an area PV.
4. Classify coverage as intrinsic production, native mask-driven production, explicit Wakemu lifecycle policy, missing publisher, conditional missing publisher, or unresolved source authority. Require production entrypoint evidence for policy events. A different source emitting the same ID does not establish coverage of the required source recipe.
5. Verify source context: actual manager, caster/target identity, running UID, spell/container, triggering value, state reference, source cell and subscription channels. External null-source events cannot provide a killer or state reference by assumption. Keep parent conditions, costs and owner prerequisites attached to findings.
6. Trace retained lifecycle independently: initial subscription installation, activation clone source, original target checks, state replacement, expiry, death/withdrawal and child cleanup. Record executor gates that skip the phase before declaring a producer complete.
7. Publish machine findings with `event_ids`, `affected_source_refs`, `affected_cra_listener_refs` (replace with class-specific naming when generalized), `source_code`, `mechanism` and `apply_to_other_classes`. Capture catalog and source hashes. Separate missing graph data, proven code gaps, conditional context gaps and gameplay verification.

The reusable gaps in `cra-event-code-audit-20261008.json` demonstrate three different failure modes: direct null400 mask6 phases omitted (2177), state-decurse321 phases absent (2288), and absent external publishers behind cosmetic conditions (1012/1015/1018). Event1010 remains missing with original timing/source unproven; actual death1013 is a distinct source. These checks apply across all classes without spell-ID exceptions.

This procedure is read-only. Automated execution and manual client acceptance belong to later verification stages; static event coverage does not certify class mechanics.
