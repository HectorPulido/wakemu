# Wakemu external cast boundary policy

Normal validated spell transactions now deliver external event 1024 before the first root and 1025 after all roots complete successfully. Both boundaries execute after validation, resource spending and cast-facing setup, inside the same unpublished preview and active-spell scope as the roots. A callback exception rejects the complete transaction; a failed root never emits the successful-after boundary. Effect packets remain private until the existing commit succeeds.

This timing is explicit **Wakemu server policy**, not a recovered original-server callsite. The installed native `eFK.pyl` classifies these integers as external events, and the complete 178,337-definition native inventory finds zero published `aZO` producers for either. The subscriber definitions establish relevant eligibility: Cra 350554 uses 1025 to select active spell branches and apply caster states 7758/7760/7793; 351403 and 352326 use 1024 with their original active-spell and state conditions. Those conditions remain unchanged. Selecting before/after order supplies a coherent server boundary without pretending that criterion context itself was a native emitter.

Delivery uses native null-source selection: local channel 6 and reversed channel 60 address the actual caster's manager; channel 61 visits the captured native global PV iterator. Registered areas with null Qf receive no retained-manager delivery. No fictitious running-effect UID, caster/target trigger binding, source spell container or damage event is fabricated. Each listener retains its original PL and actor bindings, while current fight PZ identifies the cast being executed. The global iterator is constructed after local reactions, preserving the shared collection producer. A missing legacy global topology rejects an observable global delivery rather than reconstructing order from a Python roster.

The reusable `cast_event_scope` API accepts separate normal and nested cast origins. A nested effect-426 cast enters under its own active spell and level; finishing it restores the parent scope. Executing child effect groups or restoring retained effects does not create another cast boundary. A custom dispatcher with no native retained-event subsystem has no Qf callbacks to deliver.

The normal integration is `prepare_spell_transaction`, covering connected player casts and owned summon casts already authorized by the shared casting pipeline. NPC spell production is outside this class-spell task. No live configuration, service, Docker or AI source is modified.

Pure regressions cover native mask routing, captured global order, current-spell ownership, nested boundaries, rejected callback/root/post-cast paths, and transaction-preview/RNG isolation. The original Cra active-spell eligibility expressions are evaluated through the shared criterion evaluator. Full class-state application and beacon reactive HP loss still require production runtime integration validation; these pure tests do not certify whole-class gameplay.
