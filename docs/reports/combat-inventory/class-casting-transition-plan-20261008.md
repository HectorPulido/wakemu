# Automatic conditional casting transition plan

The [machine-readable plan](class-casting-transition-plan-20261008.json) joins the651 conditional branches to the completed all-class normal baseline:73 legal decks,635 ordinary spell/level pairs, `finished=true` and `source_stable=true`. It also consumes the actual M2 committed-state evidence. No runtime catalog or native export was executed by this planner.

458 branches have positive state transition candidates;193 instead require non-state facts, negative/upper-bound state conditions, or another typed preparation. Calls that only test an upper bound or absence do not become instructions to apply a state. The plan retains the original complete criterion, thresholds, selector and remaining preparation domains.

The positive requirements produce433 actual-Ready retained-trigger candidates,127 ordinary class-owned caller candidates and7 requirements without an owned producer in the current index. These are requirement occurrences, not distinct states or a mechanical completion percentage. Innate dependency ownership includes descendant applicators, not just direct seed IDs. Those applicators still need their real triggering event and guard; production Ready does not automatically apply every descendant state. Candidate source guards produce one detected positive-state cycle. That cycle does not prove unreachability: an alternate actual source or initialization can break it. Likewise, a missing indexed family304/innate path does not prove absence of a captured/copied/profile-initialization producer.

Each proposed transition has this execution contract:

1. Run production Ready and capture actual class, owned deck/grants, actor/cell target and ledgers.
2. Choose a compatible actual-owned source spell from the indexed native state applicator ancestry. Resolve its own prerequisites and native selector before casting; do not directly execute its descendant applicator.
3. Commit a normal source request and verify that the desired state appears on the correct actual actor with the required level. Keep the observed target binding, guard and turn timing.
4. Execute the original conditional spell on that same committed snapshot and record the exact selected branch and costs/range/LOS/cell flags.
5. Execute the original removal/toggle/expiry path and repeat the original request as a control. A direct ledger deletion is not a removal proof.

The baseline observations are linked to candidate source spells and conditional spell references, including actual grant origin, prepared targets, costs and representative commits. A successful ordinary spell transaction alone does not identify which conditional branch was selected, and the baseline does not supply the complete post-commit state ledger/selected-branch identity needed to close these branches. Every changed cost/range/LOS flag therefore remains explicitly pending exact branch evidence. The normal baseline's success count is not reused as conditional coverage.

Actual committed M2 evidence provides newly present or changed state facts relevant to14 branches. This is partial preparation evidence, not14 completed conditional cases. The planner keeps scenario identity, before/after populations and immediate state level. In particular, Precision30 after Fulminante and Tiro Preciso from a separate prefix experiment cannot be merged into one simultaneous prepared state. No next-turn persistence is inferred. The pending same-turn wall follow-up must establish their joint criterion and restored restrictions.

The normal bulk audit owner has been asked to capture selected conditional identity and before/after owner/target state ledgers in its next general execution. This closes the same evidence gap for all classes rather than requiring a hand-built test for each spell.
