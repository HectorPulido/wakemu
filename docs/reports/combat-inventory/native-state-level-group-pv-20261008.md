# State-level group844 generic PV correction

Production relative probability was already implemented in `EffectDispatcher`: native candidate eligibility and independent sampling happen at parent level, followed by the shared eVt probability-bypass context and ordered limit executor. The stale standalone844 doc did not describe that production route. No relative selector refactor or guessed RNG was added.

The concrete production gap was `eYr.d(eZR,boolean)` level sourcing. Original bytecode first calls inherited `eYg.d`, chooses caster/target after the group rebind, then reads **generic `PV.bax()`**, not a fighter-only actor dictionary. It scans the Qf iterator for the first matching eZk state. A null PV immediately preserves the parent context. A nonnull PV with null Qf proceeds to the optional tenth-parameter constant. Unknown identity is not native null.

`runtime_child_level` now resolves registered/detached fighters and verified registered/retired area PVs. It preserves known null-Qf absence without inventing a ledger, rejects missing nonnull identities, and computes the original first-state/factor/constant formula. Both production call sites use it: runtime group evaluation and retained eVt context construction. Null-target actor rebind1/2 now preserves the original actors, matching `eYg.fPP`.

Original `eYg.a(iterator,Qe,boolean)` calls the virtual derived `d` **before** its flag16 sentinel-transmission check. Existing sentinel transmission therefore remains unchanged: an explicit calculated SP=-1 can still transmit fRR under flag16. No alternate provenance rule was introduced.

The actual installed eYr.C/d probe `ProbeNativeStateGroupPV.java` passed18 null-PV/null-Qf cases with parameter counts7/9/10 and constants-1/0/3, without loading a runtime catalog or starting a service. Python regressions are prepared for area Qf, known null-Qf versus nullPV, null-target rebind, unknown identity and matching child evaluation/wire level; execution is deferred to the validation agent.
