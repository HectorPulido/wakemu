Existing evidence separately covers an actual capture mark/death transaction, offline restoration/creation and generic summon registration. The common serialization correction is tracked across creation, movement, turn, reconnect and retirement, but Osamodas's family-324 route needs the same end-to-end checkpoints.
3. **The ordinary Osamodas spell path has known historical leads, not a current complete failure matrix.** The old critical audit of 7317 reached unsupported `HasWorldProperty`; a 2026-10-03 report records the user's Desplume7318 orientation/synchronization issue. These are evidence to replay with current sources. An old handler binding, rejected partial audit, or stale report does not prove today's cast outcome.
4. **A Ready gate pass does not certify class mechanics.** The deployment gate recorded Osamodas breed2 level200 at 18/18 Ready cases and two transitions, explicitly without GUI. This is deck/Ready coverage only.
5. **The system acceptance already written is useful and appropriately conservative.** [manual-osamodas-system-20261008.md](manual-osamodas-system-20261008.md) covers capture, persistence, captured deployment, an actual summon turn, dragon transformation, cleanup and reuse, while marking the unknown captured-summon cost instead of guessing it.

## Transferable shared fixes and limits

- **Cra summon recognition fix:** registered class summons must serialize native summon identity from validated registration authority on stat updates, movement, turn/recovery, active join, spectator and retirement routes. This applies to captured324 summons even though their creation producer differs. It does not establish that every route or the current deployed image contains the correction.
- **Native summon count contract:** absent breed histogram keys mean zero only when the producer attests a complete native count. Unknown totals remain unknown. Do not substitute registration length, HP, team, or Symbiot slot count.
- **Cra area-selection correction:** non-point native area selectors may enumerate actual occupants when selector1 is present; point selectors and null/zero selectors retain transmitted PV. Apply to Osamodas area effects only after checking the actual native area and selector; do not broadly rewrite point-targeted spells.
- **Sacrier relationship selector correction:** relationship-based fresh-child selection is shared and can matter for allied/controller/summon reactions. Preserve the original triggering owner and direct relationship facts; do not copy Sacrier-specific state IDs or predicates into Osamodas.
- **Iop/Sacrier transaction safeguards:** prepare/commit isolation, resource accounting, RNG rollback and state/effect ownership boundaries are common. Their class formulas, passive criteria and removal semantics are not transferable.
- **Summon lifecycle contracts:** family307's event2130 addition is distinct from captured324's inherited event0. Keep actor UID, running-effect UID, owner/controller/root and physical carry separate. A creation effect's cleanup does not itself remove the creature.
