# Bulk class cast target selection

The grant-access audit no longer treats rejection at a fixed self/enemy/three-nearest-cell fixture as evidence of an effect-engine failure. It searches up to 256 distinct actual actor and walkable cells, prioritizing the enemy, self and allied actor positions, then ordered nearby map cells. At most three targets accepted by the full production cast validator proceed to effect execution.

One private fight copy and the already-created runtime adapter serve all candidate validations. The production validator selects native conditional tables and checks ownership, resource costs, range, alignment, QI, conditions and usage. Candidate validation does not spend resources or execute effects. State-dependent follow-up spells run a fresh selection against the actual post-cast draft, rather than reusing the original target list. No states, resources, terrain or spell permissions are injected.

Every checked rejection retains its target, error and available native decision diagnostic. Known validation negatives require an actual native casting result or an explicit resource/alignment rejection code; an unexplained ValueError remains unknown authority. Results distinguish eligible targets, complete searches with no eligible context, unresolved authority and truncated bounded searches. Candidate count, checked count, limit, truncation and search completeness are recorded. Reaching three accepted targets stops the search and is not a completeness claim.

Effect transaction failures occur only after a target passes validation and are labeled separately. Source hashes include the grant audit and selection helper. Pure regressions cover a legal target beyond the old three-cell sample, truncation, unknown authority, typed rejection classification, one private snapshot and actual-cell deduplication. Full bulk execution is delegated to an immutable validation snapshot; improved gameplay coverage is not claimed until that audit completes.
