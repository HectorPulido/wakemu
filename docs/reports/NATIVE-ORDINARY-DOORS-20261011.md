## Server behavior

`maps/environment_doors.py` validates the exact native action, current installed object identity and payload hash, selected owned session, durable combat exclusion, live occupation and existing interaction-range policy. Private instances are excluded. State changes serialize by map/object and persist under `(map_id,instance_id,object_id)`; opening or closing again is idempotent. No key, fee, reward, unlock or quest completion is invented.

The12344 update changes the original partial field2 state and its two native collision bits, preserving visibility, usability and all unrelated flags. A read-only original-client Java oracle consumed actual server updates in the sequence open→close→open and proved states0→1→0, both native collision bits false→true→false, with usable/visible remaining true. Private output: `board-oracle/door-native-state.log`.

Scene snapshots restore committed state on reconnect and publish only registered nearby identities. Exploration movement rejects entry into a closed cell and diagonal corner bypasses. Departure from a newly closed starting cell remains possible, and closing onto a selected online actor already occupying the door cell is rejected. These are explicit server anti-entrapment rules; no combat movement graph is modified.
