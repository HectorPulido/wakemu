# Wakemu NPC area-recipient preflight

This is an explicit Wakemu server policy reconstructed from authoritative spell ownership, effect selectors, geometry, criteria, and existing shared handlers. It is **not** a recovered original server NPC casting implementation.

The installed client `fcj` preflight validates the fighter occupying the targeted anchor against root selectors. Some NPC spells have range zero and an area that excludes the caster. Their anchor is the caster, but their intended effect recipients are other actors. The client anchor preflight consequently returns `twE` even when a valid area recipient exists.

`combat_npc_area_preflight.py` supplies a separate preflight only from the owned NPC casting entrypoint. Player/class casting retains its existing producer. The policy initially accepts exact `fcE` masks9 (enemies in the area),129 (other allies in the area), and257 (other actors in the area), with known nonpoint geometry, immediate leaf roots, and range zero centered on the actual ordinary NPC. Summons, controlled actors, withdrawn/dead casters, foreign anchors, unknown selectors, point areas, child graphs, and subscriptions do not qualify.

The ordinary casting query runs first. Only an aligned `twE` result is eligible for this explicit NPC policy. Other rejection codes remain unchanged. A private fight copy and the same effect runtime factory select actual recipients using the common native resolver, target metadata, effect criteria, and handler eligibility. Healing additionally requires a living injured recipient. No recipient is manufactured and this preflight applies no effect or resource change.

The dedicated NPC casting context changes only the root-selector acceptance hook to use those selected recipients, then repeats the complete native casting eligibility check. Anchor target identity remains the caster. Resource costs, usage limits/cooldowns, range, QI, line of sight, cast criteria, ordering, and actual transactional effect execution remain mandatory. Mandatory unsupported branches still fail the complete transaction.

The native global-population selectors used by spell3141 are supported as a distinct explicit mode: exact `fcE` masks8 and140737488355584, `area_class=anA`, and `area_native=empty`. Native bit1 is absent, so the shared resolver selects actual population recipients without area filtering. This is not an invented infinite radius. Effect80577 still requires `HasState(1579, "target")`; effect80576 still selects enemies. Unknown geometry or other masks remain rejected.

The new test module `test_combat_npc_area_preflight` covers qualification, native selector scope, resources, cooldowns, geometry, unknown conditions, missing handlers, full-health/dead/withdrawn recipients, unchanged original decisions, and caster restrictions. Native preview and commit/rollback evidence must additionally pass before publishing any newly activated monster.

The selected checks passed:24 new server policy tests and3 new SDK entrypoint tests. The SDK checks prove that NPC actions use the common policy, players retain their original condition producer, and unowned actions reject before policy selection. Preliminary native previews validated all6 owned spell/level cases for2617, including its wounded-ally healing scenario, and all4 cases for2199. Final complete cohort and transactional delivery receipts are maintained separately.

Spell3141 has a legitimate stochastic state application: effect80576 applies state1579 with a base75% chance, independently of its outer effect probability100%. `NativeStateHandler._application_chance` retains native state-resistance modifiers and the live transaction draw. A fresh cast can consume its native resources without changing a recipient when that draw rejects; effect80577 also correctly skips until its required state1579 exists. The private SDK proof harness permits at most12 fresh independent trials only after observing this exact native chance rejection. It records every failed attempt and random draw; it never forces a seed, changes chance, or reuses an already committed fight. Mandatory failures and other zero-effect cases remain failures.
