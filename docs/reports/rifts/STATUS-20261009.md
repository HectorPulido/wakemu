# Dimensional rift evidence audit — 2026-10-09

Scope: offline installed client/catalog evidence; no service restart, deployment or gameplay/database mutation. [Structured inventory](inventory.json) contains exact species references, Spanish names, native objects, exits, portal coordinates and source hashes. Pools describe eligible species, not exact wave rosters or spawn weights.

## Findings

The installed client has 17 native infinite-wave definitions in binary table 147 (`aLF`), but only 10 have public dungeon definitions: seven classic and three ultimate. The remaining seven are retained as unlinked data, including Test, discovery modes, Rushu, Toross and Shoot'Love Hall. They must not automatically be exposed as seven extra public rifts.

The dungeon definitions have empty monster pools. Their `raw_cnl` field links exactly to table147 IDs, which contain the real species pools. `baV` loads `aLF` into `byY` / `byX`; `bpZ.aWb` reads `byY.rI` as the level, `bpZ.arM` reads `cpb` as the interior map and `bpZ.getName` uses category89 plus `cpc`. `cpf` is the exterior world-map reference used with localization category77; it is not the interior. `aLH.cnn` maps through `eQM.dJ` to classic/ultimate type. All ten identities match exact native links and maps, without fuzzy names.

## Gameplay and version evidence

[Ankama's official Steam announcement for 1.72/1.73](https://store.steampowered.com/news/posts/?appids=215080&enddate=1638936299) confirms the system launch and later Amakna/Osamosa additions. [Official update announcements containing the Shustuft additions](https://store.steampowered.com/news/posts/?appids=215080&enddate=1680752356&feed=steam_community_announcements) identify a classic and ultimate rift with exclusive sublimations. These are primary publisher announcements.

The [official dimensional-rift devblog](https://www.wakfu.com/en/mmorpg/news/devblog/tickets/1335574-devblog-dimensional-rifts) returns an anti-bot page in this environment. Its historical link can be located through mirrors, but a mirror is not primary evidence and its 2021 balancing must not be silently imported. Exact formulas, random weights, artifact timing, orb behavior, survival settlement, rewards and current limits are not certified by the two publisher announcements or extracted definition table.

Installed English/Spanish UI evidence directly supports a four-character limit; ultimate-rift key requirements at combat start; rankings ordered by reached wave with monster count breaking ties; separate displayed actual completed waves and defeated monsters; seasonal/monthly rift chests containing resources and possible sublimations/pets. English and Spanish ranking-reward text differs in period wording, so exact calendar authority remains unresolved. The UI does not establish reward probabilities or cost quantities. The 2021 devblog mirror describes a 40-turn survival mode with immediate new waves, artifacts and health orbs; treat those as historical research leads until native/server authority is recovered, not a current specification.

## Actual server gaps

None of the ten rifts has a configuration in the audited generation bundle. Search of `server/wakfu_server`, migrations and `server/local_game_server.py` found no dedicated rift/wave authority, artifact selection, rift ranking settlement or 40-turn survival controller. Generic combat, loot and transport infrastructure exists, but does not implement those semantics. Absence of a dedicated named controller alone is not proof that every underlying effect is unsupported; it establishes that these ten systems are not certified or ready to test as complete rifts.

Required implementation evidence before gameplay work:

1. Decode native InfiniteWaves portal action and interior start activator, including key reference/consumption and level/member validation.
2. Recover wave-generation weights, enemy level/scaling, starting-wave formulas and turn budget from server-owned evidence or controlled official captures. Client species lists alone cannot infer these.
3. Extract artifact states/effect descriptors and health-orb appearance/cell triggers, distinguishing transient combat state from normal world corpses.
4. Implement wave lifecycle within one fight, correct timeline insertion, reconnection and late-observer replay, using existing shared combat contracts.
5. Define survival/reward escrow and exactly-once settlement, ranking values and period boundaries, then validate the complete system.

The user's request to open dungeons regardless of missions does not automatically define free ultimate-rift keys or bypass all nonquest eligibility checks. No access policy or combat implementation changed in this research.

## Reproduction and validation

Run from repository root:

```sh
mkdir -p .runtime/local/rift-review
javac -proc:none -cp 'client/lib/*' -d .runtime/local/rift-review sniffer/java/ExportInfiniteWaveEvidence.java
java -Djava.awt.headless=true -cp '.runtime/local/rift-review:client/lib/*' ExportInfiniteWaveEvidence .runtime/local/rift-review/native-infinite-waves.json
python3 server/tools/build_rift_inventory.py
PYTHONPATH=server python3 -m unittest server/tests/test_rift_inventory.py
```

The Python extractor reuses the dungeon inventory/catalog exports already created in a read-only transaction. Missing/ambiguous native links and map mismatches fail closed. Five fixture unit tests passed; native export produced17records and the join10publicrifts. This validates extraction, not playable rift mechanics.
