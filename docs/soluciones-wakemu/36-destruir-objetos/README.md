### Contrato nativo confirmado

En `client/lib/wakfu-client.jar`, el flujo del inventario entra en el modo `recycleInventory`, filtra la selección mediante `fpB.f(item, character)` y muestra una confirmación antes de enviar `cnz` (opcode **12787**). Su cuerpo es un `i16` con el número de objetos seguido de ese número de UID `i64`. Una selección vacía solo muestra `inventory.recycle.none.selection`.

La evaluación nativa distingue objeto no reciclable, objeto con ranuras y objeto con bonus sin identificar; la UI presenta `recycling.error.item.not.recyclable`, `recycling.error.item.slotted` o `recycling.bonus.item.not.identified`. También bloquea el reciclado durante combate. Esto prueba que el botón y su productor existen en el cliente; no prueba por sí solo qué artículos concretos admite el catálogo del servidor ni qué producto corresponde a cada uno.

El cliente espera `cwS` (opcode **12890**) con dos enteros `i32`. La localización nativa interpola el segundo como objetos destruidos y el primero como recursos recuperados (`recycle.resultMessage`).

El catálogo nativo `foh` define `NOT_RECYCLABLE` (0), `SHARD` (referencia 27083) y `POWDER` (referencia 27093). El exportador [ExportRecyclingMetadata.java](../../../sniffer/java/ExportRecyclingMetadata.java) conserva las 20.230 referencias `aLO` desde `bIJ.f`/`fpC`, con 0 errores, factores, flag variable, nivel, slots, flag `NOT_RECYCLABLE` y criterios; el artefacto es [item-recycling-metadata.json](../../../server/protocol/item-recycling-metadata.json). Hay 10.932 definiciones SHARD, 2.765 POWDER y 6.533 NOT_RECYCLABLE. SHARD siempre apunta a 27083 y POWDER a 27093. El catálogo también muestra 44 definiciones SHARD que tienen el flag `NOT_RECYCLABLE` activo, una anomalía conservada tal cual.

La elegibilidad del filtro `fpB.f` no usa el nivel ni los slots de equipo como límites. Rechaza el tipo `NOT_RECYCLABLE`, el flag `NOT_RECYCLABLE`, las referencias deshabilitadas en la configuración del cliente y un criterio `DELETE` falso evaluado para el personaje; luego informa por separado si el objeto tiene sockets ocupados. Se exportaron 24 criterios `DELETE`: 21 son literalmente `False` y los otros requieren el logro 1409, la instancia 702 o una instancia distinta de 1076 y 1073. Los criterios `EQUIP` se conservan como datos, pero el filtro de reciclaje no los evalúa.

El preview agrupa por referencia de producto. `fpB.cN(item)` multiplica el factor nativo por la cantidad del stack; el factor elige `yield_high` cuando es no negativo y, si no, `yield_low`. Para filas con `variable_yield`, el objeto no identificado aplica un multiplicador 1.2. `UP.bu(float)` presenta floor y ceil como intervalo de vista previa. Por ejemplo, la referencia 12 produce un factor 0.07874507 y el producto 27083; la referencia 27083 tiene producto 27093 y factor efectivo 1.0. Estos son cálculos del preview, no un sorteo autoritativo del servidor ni una implementación de reciclaje.
